## 1. Executive Summary

QuickServe (an Expo SDK 56, managed-workflow app) was linked to a newly created
Expo/EAS project and its build configuration was validated end-to-end short of a

## 2. Objective & Non-Goals

**Objective:** Initialize and validate QuickServe's native EAS build environment,
attempt an Android development/preview build, and — where feasible on an available
emulator — perform a limited, non-destructive native smoke test.

**Non-goals (explicit):** No full native UI certification; no complete
customer/provider journey testing; no product-behavior changes to force a passing
build; no unrelated features; no store submission; no production release; no OTA
publish; no destructive credential operations.

## 11. Android Build Result

- **Attempt 1 — ERRORED** (`EAS_BUILD_UNKNOWN_GRADLE_ERROR`). Root cause pulled from
  the raw gradle log (via the Expo GraphQL API): the **only** failed task of 451 was
  `:app:createBundleReleaseJsAndAssets_SentryUpload_…`, where the
  `@sentry/react-native` gradle hook ran `sentry-cli` and exited 1 with
  `error: An organization ID or slug is required (provide with --org)`. The Sentry
  plugin in `app.json` has empty `organization`/`project`, so the release-variant
  source-map upload cannot run. Everything else (React Native, react-native-screens,
  all native modules) compiled with only deprecation warnings.
- **Fix (build-config only, not product behavior):** set
  `SENTRY_DISABLE_AUTO_UPLOAD=true` as an uncommitted EAS env var for the `preview`
  environment. This disables the build-time source-map **upload** step only; runtime
  Sentry init and all committed config are unchanged.
- **Attempt 2 — FINISHED (success).** Profile `preview`, Android APK, ~111 MB,
  internal distribution. Build id `93610f72…` (redacted tail). Both Supabase env
  vars + the Sentry flag were loaded from the `preview` environment; keystore reused
  from attempt 1. Artifact downloaded and verified as a valid APK.

## 19. Defects / Blockers

1. **Build blocker (resolved) — Sentry source-map upload.** First build errored
   because the `@sentry/react-native` gradle hook ran `sentry-cli` with an empty
   org (§11). Classification: **build configuration**. Resolved via the
   `SENTRY_DISABLE_AUTO_UPLOAD` build flag (no product/repo change). A proper
   long-term fix is to configure a real Sentry org/project/auth token (or disable
   upload in the plugin config) — deferred; out of Phase 3B scope.

2. **Finding (open, NOT fixed) — infinite render loop on the admin login→dashboard
   transition.** Reproducible: signing in as an admin on the native build throws
   `Error: Maximum update depth exceeded. … React limits the number of nested
   updates to prevent infinite loops.` Component stack:
   `NativeStackNavigator → RootNavigator → ErrorBoundary → RootLayout`. The error
   boundary catches it gracefully (no crash; "Something went wrong / Try again").
   **Expected:** login navigates to the admin dashboard. **Actual (live transition):**
   render-loop → error boundary. **However**, a cold relaunch with the restored
   session renders the dashboard correctly with live QA data, so the loop is
   specific to the live transition path, not a broken screen. Per phase rules this
   was **reproduced, logged, and left unfixed** (product behavior, out of scope).
   Classification: **product runtime defect (render loop)**, gracefully contained.

3. **Observation — native entry surface.** The standalone build's unauthenticated
   entry screen is the **Admin Panel** login (a web-oriented surface). Customer /
   provider *mobile* onboarding surfaces were not the default entry and were **not**
   exercised in this smoke; their native certification remains deferred (§21).

4. **`expo-doctor` advisory** (§13) — 11 Expo packages one patch behind latest
   SDK-56 patch. Informational, not a defect.

5. **Build-queue latency** — the free-tier EAS build queue delayed attempt 1 by
   ~40 min (external infrastructure); attempt 2 queued only briefly. Not a repo issue.

## 20. Pilot-Readiness Impact

the project is linked, profiles are separated, environment injection works, both JS

UI/journey certification remains a separate, later phase.
